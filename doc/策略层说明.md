# 策略层说明

## 问题背景

pmbot 的大脑（Brain）是一个**控制系统**，而不是传统意义上的策略。它输出的是**意图（Intent）**，而不是具体的交易指令。

### 当前问题

Brain 生成的 Intent 包含：
- `BiasYes`: 偏向YES还是NO（-1到1）
- `RiskDeltaMax`: 允许的风险增量
- `ModeMix`: Normal/Shock模式混合（0到1）
- `Freeze`: 是否冻结

但是，**如何将这些意图转换为具体的订单**，当前实现过于简单：

```go
// 当前实现（internal/oms/oms.go:desiredOrder）
func desiredOrder(t types.MarketTick, in types.Intent) (types.Side, float64) {
    if in.BiasYes > 0 {
        return types.SideYes, t.BestAsk  // 简单买入YES
    }
    return types.SideNo, 1 - t.PYes  // 简单买入NO
}
```

### 缺失的功能

1. **双向持仓管理**：如何平衡YES和NO的仓位
2. **仓位感知**：当前仓位如何影响下单决策
3. **模式切换**：Normal模式和Shock模式的不同执行逻辑
4. **价格优化**：是否应该挂单（提供流动性）还是吃单（消耗流动性）
5. **风险分配**：如何将RiskDeltaMax分配到YES和NO

## 解决方案：策略执行器（Strategy Executor）

### 架构设计

```
Brain (控制系统)
  ↓ 生成 Intent
Strategy Executor (策略层) ← 新增
  ↓ 生成 OrderDecision[]
OMS (订单管理)
  ↓ 执行订单
交易所
```

### 策略执行器的职责

`internal/strategy/executor.go` 实现了策略执行器，负责：

1. **双向持仓计算**
   - Normal模式：保持YES/NO相对平衡
   - Shock模式：允许不对称持仓

2. **仓位感知决策**
   - 根据当前YES/NO仓位决定是否需要调整
   - 考虑仓位置信度（confidence）

3. **价格优化**
   - Normal模式：使用ask价格（吃单，更激进）
   - Shock模式：使用midpoint价格（挂单，更保守）

4. **风险分配**
   - 根据ModeMix和BiasYes分配RiskDeltaMax到YES和NO

### 使用方式

#### 方式1：在Engine中集成（推荐）

```go
// internal/engine/engine.go
import "polymarket-btc-bot/internal/strategy"

// 在Engine中添加策略执行器
type Engine struct {
    // ... existing fields
    strategy *strategy.Executor
}

// 在handleEvent中调用
func (e *Engine) handleEvent(ctx context.Context, ev types.Event) {
    // ... 
    case types.EventMarketTick:
        // ... 
        var intent types.Intent
        if e.brain != nil {
            intent = e.brain.Decide(tick, e.signals, e.lastRisk)
        }

        // 使用策略执行器
        if e.strategy != nil && e.pos != nil {
            yes, no, _, conf, _ := e.pos.Snapshot()
            posSnap := strategy.PositionSnapshot{
                YesShares:  yes,
                NoShares:   no,
                Confidence: conf,
            }
            decisions := e.strategy.Execute(tick, intent, posSnap)
            
            // 将decisions转换为订单
            for _, dec := range decisions {
                if dec.CancelAll {
                    e.oms.CancelAll(ctx, e.market)
                    continue
                }
                // 调用OMS下单
                // ...
            }
        } else {
            // 回退到简单逻辑
            e.oms.OnIntent(ctx, intent, e.market)
        }
}
```

#### 方式2：通过OMS接口（当前实现）

OMS已经预留了策略执行器接口，但需要解决循环导入问题。

### 策略逻辑说明

#### 1. 目标仓位计算

```go
// Normal模式：平衡持仓
normalYesAlloc = 0.5 + biasYes * 0.2  // 轻微偏向
normalNoAlloc = 1.0 - normalYesAlloc

// Shock模式：方向性持仓
shockYesAlloc = 0.5 + biasYes * 0.4  // 强烈偏向
shockNoAlloc = 1.0 - shockYesAlloc

// 混合
yesAlloc = modeMix * normalYesAlloc + (1-modeMix) * shockYesAlloc
```

#### 2. 价格计算

```go
// Normal模式：吃单（使用ask价格）
if modeMix > 0.5 {
    price = tick.BestAsk
}

// Shock模式：挂单（使用midpoint）
else {
    price = (tick.BestBid + tick.BestAsk) / 2
}
```

#### 3. 订单生成

- 计算当前仓位到目标仓位的差值
- 如果差值超过最小订单大小（5 shares），生成订单
- 限制同时只有一个未完成订单（OMS的安全机制）

策略执行器填补了Brain控制系统和实际下单之间的空白。它实现了：
